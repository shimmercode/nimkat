## ۱) پروژه چه چیزی هست و روی سرور چه چیزی اجرا می‌شود

«نیمکت» یک **سامانهٔ آموزش آنلاین** است با سه جزء:

| جزء | تکنولوژی | نقش |
|---|---|---|
| **فرانت‌اند** | Next.js 16 (App Router) + React 19 + Tailwind 4 | ۴۸ مسیر صفحه، SSR، راست‌به‌چپ |
| **بک‌اند / API** | Node.js 22 + Express 5 | همهٔ منطق کسب‌وکار، ۲۰۰+ endpoint |
| **پایگاه‌داده** | SQLite (better-sqlite3) با حالت WAL | تراکنش‌های مالی، رزرو، کیف پول |
| **Reverse Proxy** | Nginx 1.27 | یکپارچه‌سازی `/api` و `/api/events` (SSE) |

**نکتهٔ کلیدی معماری:** هر دو جزء با **Docker Compose** روی **یک سرور** اجرا می‌شوند و از طریق شبکهٔ داخلی Docker با هم ارتباط دارند:
```
nginx (:80) ──/api/──────► backend (:8000) ──► SQLite (/data)
        │
        └──/────────────► frontend (:5173) ──► API_INTERNAL_URL
```

> ⚠️ **این یعنی یک سرور کافی است** — نیازی به دو سرور جداگانه (فرانت و بک‌اند) نیست. این مهم‌ترین نکتهٔ صرفه‌جویی در هزینه است.

## ۲) محاسبهٔ منابع مورد نیاز (بر اساس کد واقعی، نه تخمین)

### مصرف حافظه (RAM) در زمان اجرا
```
Next.js SSR (۴۸ مسیر + sharp)  →  ۳۰۰ – ۵۰۰ MB
Express + better-sqlite3         →  ۱۵۰ – ۲۵۰ MB
Nginx                           →    ۲۰ MB
OS + Docker Engine               →  ۴۰۰ – ۷۰۰ MB
────────────────────────────────────────────────
جمع پایه (Baseline)              →  ۰.۹ – ۱.۵ GB
```
### مصرف دیسک
```
ایمیج Docker فرانت‌اند  →  ۹۰۰ MB – ۱.۲ GB
ایمیج Docker بک‌اند     →  ۴۰۰ – ۶۰۰ MB
Nginx                   →    ۵۰ MB
بکاپ SQLite + لاگ‌ها    →  ۱۰۰ – ۵۰۰ MB (رشد پیوسته)
────────────────────────────────────────────────
جمع                     →  ۲ – ۳ GB
```

### نتیجه‌گیری — سه سناریوی پلن

| سناریو | CPU | RAM | دیسک | ترافیک ماهانه | توضیح |
|---|---|---|---|---|---|
| **دمو / ارائه به کارفرما** | ۲ هسته | ۲ گیگ | ۴۰ GB SSD | ۱۰۰ GB | فقط ترافیک کم |
| ⭐ **پیشنهادی — بهره‌برداری واقعی** | **۴ هسته** | **۸ گیگ** | **۸۰–۱۰۰ GB NVMe** | **نامحدود یا ۱ ترابایت** | جای رشد تا تست بار |
| **پس از تست بار موفق** | ۶–۸ هسته | ۱۶ گیگ | ۱۵۰–۲۰۰ GB NVMe | ۱ ترابایت+ | پس از تأیید کارفرما |

### چرا ۸ گیگ و نه ۴ گیگ؟
پروژه سه چیز دارد که **رم زیادی می‌خواهند** و در تست بار (که در مرحلهٔ نهایی قرار است اجرا شود) این موضوع حیاتی می‌شود:
1. **تست هم‌زمانی رزرو** روی یک ظرفیت محدود (مثلاً ۱۲ صندلی) — چند درخواست هم‌زمان + قفل تراکنش
2. **پردازش تصویر با `sharp`** — تا ۲۴ مگاپیکسل ورودی، رم‌خور و CPU‌خور
3. **SSE (`/api/events`)** — اتصال‌های زندهٔ هم‌زمان با `proxy_read_timeout 3600s` روی nginx

> **پیشنهاد قطعی:** پلن **۴ هسته / ۸ گیگ / ۸۰ گیگ NVMe** بگیرید. با قیمت حدود **۱.۴ تا ۲.۲ میلیون تومان** ماهانه در بهترین حالت، بالاترین حاشیهٔ اطمینان را می‌دهد و اگر بعداً تست بار موفق بود، بدون تغییر سرور قابل بهره‌برداری است.

### ب) گواهی SSL
- **Let's Encrypt** — رایگان، تمدید خودکار. روی nginx با `certbot` یا در پنل پارس‌پک (SSL رایگان روی بیشتر سرویس‌ها).
- ⚠️ **نکتهٔ مهم:** گواهی SSL از نوع **DV** (اعتبارسنجی دامنه) با **IP ایران** برای برخی سرویس‌های بین‌المللی مشکل‌ساز است. چون سایت روی سرور ایران است، Let's Encrypt با DNS-01 (کارفرما باید دسترسی DNS داشته باشد) یا HTTP-01 پیشنهاد می‌شود.

## ۶) مراحل عملی استقرار (خلاصهٔ دستورها)

این پروژه با `docker-compose.yml` آمادهٔ استقرار است. پس از خرید سرور:

```bash
# ۱) اتصال SSH
ssh root@SERVER_IP

# ۲) نصب داکر + compose (با آینهٔ داخلی پارس‌پک برای سرعت)
curl -fsSL https://get.docker.com | sh
# تنظیم registry-mirror طبق: docs.parspack.com/reference/mirror/docker/

# ۳) کلون ریپو
git clone https://github.com/shimmercode/nimkat.git && cd nimkat

# ۴) تنظیم متغیرهای محیطی (توکن‌ها از کارفرما)
cat > .env <<'EOF'
NIMKAT_SECRET=<حداقل ۳۲ کاراکتر تصادفی>
NIMKAT_SETTINGS_KEY=<۶۴ کاراکتر hex>
PUBLIC_SITE_URL=https://nimkat.ir
SITE_URL=https://nimkat.ir
APP_ORIGINS=https://nimkat.ir
COOKIE_SECURE=true
COOKIE_SAME_SITE=lax
TRUST_PROXY=1
NIMKAT_HTTP_PORT=8080
EOF

# ۵) اجرا
docker compose up -d --build

# ۶) بررسی سلامت
curl http://127.0.0.1:8080/api/health
docker compose ps
```

## ۹) هشدارهای فنی که باید در مستندات خرید لحاظ شوند

1. **تحریم Docker Hub و npm** — حتماً از مخازن داخلی استفاده شود، وگرنه build شکست می‌خورد.
2. **Node.js 22 لازم است** — `better-sqlite3` و `sharp` با نسخه‌های قدیمی Node کامپایل نمی‌شوند (نیاز به `python3 make g++` در بیلد).
